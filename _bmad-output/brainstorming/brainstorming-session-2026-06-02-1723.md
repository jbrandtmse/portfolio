## Phase 4 — First Principles (Technical Architecture, Abacus VM)

**Environment facts in play:** OpenAI-compatible LLM endpoint (the chat agent's brain — no external API), nginx vhost hosting at `joshuabrandt.abacusai.cloud`, persistent filesystem, Postgres, S3 storage, GitHub access.

**[Architecture #A1] — "Static Film + Small Live Agent Brain"**
- _Concept:_ Split the system: the cinematic canvas, timeline, showcases, harvested artifacts, and Suno audio are **prebuilt static assets** served by nginx; only the **chat agent** runs as a small live backend.
- _Novelty:_ Fast, cheap, robust public surface with a minimal dynamic footprint.

**[Decision #35] — "Curated, Pre-Approved Demonstrations"**
- _Concept:_ The Demonstrator (#8) and agentic walkthroughs are **pre-recorded/curated**, not live arbitrary execution. Nothing appears Josh hasn't approved. They become polished, replayable static assets.
- _Novelty:_ Keeps the "live agentic work" wow without exposing a public execution engine.

**[Decision #36] — "The Grounded Advocate" (chat architecture)**
- _Concept:_ The live chat generates conversationally via the Abacus LLM endpoint but is **strictly grounded** in an approved knowledge base with guardrails and a fixed advocate persona — spontaneity in phrasing, control over substance.
- _Novelty:_ A living voice that can only speak from blessed material.

**[Decision #37] — "Git Is the Single Source of Truth (No Live Reads)"**
- _Concept:_ Everything shown is curated and checked into this repo; the site never reads GitHub/YouTube/Suno at runtime. New projects are imported deliberately; the build does the rest.
- _Novelty:_ Total editorial control + a fully static, key-free, rate-limit-free runtime — nothing unapproved ever appears.

**[Feature #38] — "The Project Import Workflow"**
- _Concept:_ A deliberate process to bring a new project into the portfolio repo — curated artifacts, timeline data, chosen media, write-up — wired into timeline, wings, and knowledge base.
- _Novelty:_ Maintenance becomes one intentional act.

**[Decision #39] — "Site Extension via BMAD Correct-Course"** ⭐ (keystone)
- _Concept:_ Adding content is itself a BMAD operation: run `/bmad-correct-course` to add a new epic/stories, then the normal dev cycle implements and deploys. The portfolio is a living BMAD project documenting its own evolution; its own `_bmad-output/` becomes Glass Box and Timeline content.
- _Novelty:_ The maintenance workflow *is* the product thesis — the site appears on its own timeline, running agentic engineering in public on the very site that showcases it. The loop fully closes.
