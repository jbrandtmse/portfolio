Accessibility / fallback notes — feeds EXPERIENCE.md

  • The positioning line is the page <h1> ("Seasoned, building at the frontier"); the wordmark, kicker, and sub-line are ordinary semantic text — the full hero message is in the initial HTML (SEO / GEO substance).
  • The fork is two real <a> links — Explore → the Scene Arc (in-page) and I'm here to book a talk → /speaking — keyboard-focusable and followable with JS off. The Guide entries are a real link / button.
  • The portrait is a styled placeholder with a text alternative (here a labeled role="img"; the real headshot will carry meaningful alt). It is not stock / AI imagery.
  • The faint drafting grid and the scene-rail tick / meter graphics are decorative (aria-hidden / pseudo-elements); no information lives only in them — scene names, "Scene 1 of 7", and link text carry the meaning in the DOM.
  • Under prefers-reduced-motion / JS-off this renders as a static, fully-styled hero — the opening beat is calm by design, so there is no spectacle to lose; the fork, the Guide entries, and the scene-rail links all still work.
  • The Guide pill is the single elevated surface site-wide (the one soft shadow); it is a real <button> with an accessible label. The mobile scene-rail collapses to a sticky top progress bar + "Jump to section" menu with the same targets.
  • Color is never the sole signal: the current scene is marked by text ("Scene 1 of 7", aria-current) and weight, not only the lit tick. Navy on cream meets AA (10.15:1); secondary ink meets AA (5.6:1).
  • Reading / focus order follows the DOM: wordmark → kicker → h1 → sub-line → fork → Guide entry → portrait → scene-rail → Guide pill — identical intent on desktop and mobile.
