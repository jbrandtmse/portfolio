Ask my Guide

Accessibility / fallback notes — feeds EXPERIENCE.md

  • The build-story is a real <ol> of artifact links — it works with JS off and degrades to a plain ordered list (the navy nodes/spine are pure CSS decoration drawn with pseudo-elements).
  • The spine + nodes are decorative (aria-hidden in spirit): no information lives only in the dots; the date, type, and "Read" link carry the meaning in the DOM.
  • Every card is a real link to its /glass-box/{artifact} reader — keyboard-focusable, screen-reader navigable, no JS required to follow.
  • Headings form a clean hierarchy: page h1 ("The build story") → each artifact h3. The recursion beat is a non-heading <aside>, so it never breaks the outline.
  • The live dot's halo and the "Live · in progress" pill are static (no animation) — reduced-motion safe; status is also stated in text.
  • The ghosted upcoming nodes are dashed + muted but remain real list items with text labels ("As it accrues"), not image-only states.
  • Color is never the sole signal: shipped vs live vs upcoming is also conveyed by the date, the pill text, and the dashed treatment.
  • Navy on cream meets AA (10.15:1); ink-secondary notes meet AA (5.6:1). The cross-link to /timeline and the static fallback footer keep the page reachable without the spine.
