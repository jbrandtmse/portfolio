## What could be better

1. **The same gate-attestation gap bit twice (Rule 14).** A latent `ts(2538)` shipped in 6.3 past its QA **and** code-review "typecheck green" claims, and 6.4's dev reported "All tests pass" while the gate was red. In both cases a stage asserted a gate-state it had not verified by exit code (`astro check`'s "1 error among 75 hints — Failed" is easy to misread). → **Rule 14** (every stage attests the real `pnpm test:all` exit code; a prose "green" claim is unverified; red is fixed or HALTed, never normalized as "pre-existing").
2. **An internal sentinel leaked into user-visible prose (Rule 15).** 6.1's harvest interpolated `[OPEN: no Glass Box reader yet]` into each Dot's `description`, rendering the internal "no reader yet" plumbing token as visitor copy (22× static + the 6.2 island); the 6.1 smoke missed it (checked link resolution, not description text). → **Rule 15** (carry status in structured data; strip the sentinel in a SHARED display helper used by all surfaces; test the served visible text for sentinel leakage; exempt the deliberate `[ASSUMPTION]`/`[OPEN: <reason>]` credibility flags).
3. **The 6.1 lead smoke under-scoped the credibility check.** It verified the harvested links *resolve* (200) and no `href="[OPEN]"` anchors, but did NOT scrutinize the rendered *description text* — where the sentinel was. A credibility smoke should read the visible prose, not just the link targets. (Folded into Rule 15's "test the served visible text.")
