## The Build Story

[OPEN: build video / recording URL] — a recording of the live-on-stage demo and build walkthrough will be linked here when confirmed. What is real: the BMAD Method process used to build it.

The build followed the BMAD Method pipeline exactly as this portfolio does — not as a demonstration of the method on a toy problem, but as a genuine application of it to a production domain. The phases were: brainstorm, brief, PRD, architecture, epic planning, story creation, agentic dev, code review, QA, and deployment.

Every epic was run through the full cycle. Every story had Dev Notes with real technical context — not placeholders. The code-review phase ran on a different agent model than the dev phase, by design: the reviewer has no memory of the author's reasoning, so it must evaluate the artifact on its own merits.

The build was done in the open — the same posture as this portfolio. Decisions were recorded as they were made. The architecture document tracked every constraint and every tradeoff. The retrospective (below) is real, not a curated post-hoc summary.

## Retrospective

A retrospective run at the end of each epic, following the BMAD Method. What shipped, what broke, what would change.

The retrospective is not a victory lap. It is a structured review of what the BMAD Method produced, where it struggled, and what the next build would do differently. It follows the same format as the retrospectives visible in the Glass Box for this portfolio — the questions are the same, the discipline is the same.

What the retrospective confirmed: the agentic-engineering approach does not eliminate debugging — it changes its character. Bugs in agent-generated code tend to be architectural (a misunderstood constraint, a forward-reference not resolved) rather than typographic. They surface at integration time, not at unit-test time. The BMAD Method's integration ACs and lead smoke gates catch them at exactly that moment.
